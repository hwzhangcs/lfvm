# 可用性测试方案（LFVM-Q-09）

## 目标

邀请 5 名**从未使用过任何版本控制工具**的同学，不看说明文档，独立完成 5 项任务。

- 每项任务完成率不低于 80%（即 5 人中至少 4 人完成）；
- 每项任务平均用时不超过 3 分钟；
- 测试过程中界面不出现表 8-2 所列 Git 术语（commit、branch、HEAD 等）。

## 准备

1. 在 Windows 10 或 11 电脑上安装发布版安装包，清空历史存储（`%LOCALAPPDATA%\com.lfvm.desktop`）。
2. 在桌面放一个“课程作业”文件夹，内含：`报告.docx`、`代码/main.py`、`图片/封面.png` 和一个空文件夹。
3. 准备录屏软件，每人单独测试，主持人只读任务卡，不做提示。

## 任务卡

| 编号 | 任务（原文读给参与者） | 完成标准 |
|---|---|---|
| T1 加入项目 | “请让这个软件开始管理桌面上的‘课程作业’文件夹。” | 项目出现在列表并进入概览 |
| T2 保存版本 | “请把现在的作业保存下来，名字叫‘初稿’。” | 生成 V1，名称为“初稿” |
| T3 比较两个版本 | （主持人先修改 `代码/main.py` 并让参与者保存第二个版本）“请看看两次保存之间改了什么。” | 打开版本比较并看到 main.py 的逐行差异 |
| T4 恢复单个文件 | （主持人删除 `图片/封面.png`）“封面图片不见了，请把它找回来。” | 封面.png 回到原位置 |
| T5 创建并切换方案 | “请从‘初稿’另起一个尝试，叫‘换个风格’，并切换过去。” | 方案创建成功且当前所在为该方案 |

## 结束后

- 每项任务完成率 ≥80% 且平均用时 ≤3 分钟为通过；
- 汇总“卡住的地方”，对应修改界面文字或流程后，对未通过的任务重新测试。
